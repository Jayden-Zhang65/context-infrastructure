# Workflow: LIMS 计算机化系统权限申请表（A036）填写

## 元数据

- **类型**: Workflow
- **适用场景**: 用户口述一段权限变更信息（新增/撤销/转移/修改），需要填入 `MX-SMP-ZLGL-A036_03_计算机化系统权限申请表.docx` 并保存
- **创建日期**: 2026-07-31
- **关联文件**: `LIMS/form/MX-SMP-ZLGL-A036_03_计算机化系统权限申请表.docx`、`LIMS/form/fill_a036.py`

## 目标

把用户口述的权限变更信息，转化为申请表各字段并写入 docx，输出一份可直接走审批流程的已填表。

## 边界

- 只填表，不代替审批。审批栏只在用户明确说明已批准时才填姓名，否则留空。
- 不修改模板结构（表头、行数、合并单元格）。脚本按固定结构定位单元格，模板一旦改版需同步调整脚本。
- 脚本只在 `form/` 目录创建，不生成新模板文件。

## 字段映射与默认值

用户口述通常不按表单字段组织，需要先映射。默认值来自既往填写实践，可在 JSON 中覆盖：

| 表单字段 | 口述线索 | 默认值 |
|----------|----------|--------|
| 所在部门 | 与谁/哪个部门相关 | 质量控制部 |
| 申请人 | 口述中"申请"的动作主体 | 账号归属人（谭观莲等） |
| 权限操作类别 | 新增/撤销/转移/修改 | 新增 |
| 申请日期 | — | 当天日期 |
| 申请事由 | 口述理由 | 自动生成：`因工作需要，{归属人}（工号{账号}）需{操作}权限：{角色}。` |
| 应用系统 | — | LIMS |
| 权限角色 | "XX权限"中的角色名 | 必填 |
| 账号/工号 | "账号：3132""工号3132"等 | 必填 |
| 账号归属人 | 口述人名 | 必填 |
| 可访问范围 | "可以访问XX组"的组清单 | 组清单按顿号拼接，缺省无此段 |
| 要求权限转移时间 | 仅转移/修改涉及 | 空 |
| 部门负责人审批 | "跟XX申请"中被申请的主管 | 留空 |

必填四项：账号归属人、账号/工号、权限角色、可访问范围。缺任一则先问，不要猜。

## 执行流程

用户口述 → 按上表映射为 JSON 字段 → 调用脚本 → 用脚本输出的验证结果与用户描述逐项核对 → 汇报填写结果。

脚本调用方式：

```powershell
python form/fill_a036.py <docx路径> <fields.json路径>
```

字段 JSON 结构（完整示例）：

```json
{
  "department": "质量控制部",
  "applicant": "谭观莲",
  "operation": "新增",
  "date": "2026-07-31",
  "reason": "因检验工作需要，谭观莲（工号3132）需增加LIMS系统仪器管理员权限，可访问化验室所有检验组。",
  "records": [
    {
      "system": "LIMS",
      "role": "仪器管理员",
      "transfer_time": "",
      "account_no": "3132",
      "account_owner": "谭观莲",
      "access_scope_label": "可访问化验室所有检验组：",
      "access_groups": ["理化组", "仪器(1)组", "仪器(2)组", "综合(1)组", "综合(2)组", "动物实验组", "针剂中间体检验组", "口服中间体检验组", "阳春中间体检验组", "白云厂区中间体检验组", "试剂仓"]
    }
  ],
  "approver_dept": "姚姗延"
}
```

要点：
- `records` 数组一条 = 数据表一行，模板仅两行，最多 2 条。
- `reason` 不填则脚本自动生成；`approver_dept`/`approver_qa`/`approver_it` 不填则留空。
- 组清单只覆盖部分组（非全部）时，把 `access_scope_label` 改成具体表述（如"可访问以下检验组："）。
- 若上次填过同一张表，直接沿用已填的 docx；脚本会清空上次的数据行只保留序号。

## 验收标准

1. 脚本退出码为 0，且验证输出（各 ROW 单元格内容）与用户口述的每个事实一致。
2. 必填四项齐全，操作类别只有一项被勾选（√），其余保持 □。
3. 权限详细说明包含账号/工号和组清单，组名与口述完全一致。
4. docx 保存在 `LIMS/form/`，能用 Word/WPS 正常打开。

## 已知陷阱

- **表结构依赖**：脚本按固定行索引定位（数据行从第 4 行起，部门负责人审批在第 6 行）。模板改版后行结构变化会导致错填，改版后必须用脚本验证输出核对一遍。
- **中文编码**：fields.json 必须 UTF-8。在 PowerShell 里用 `Set-Content -Encoding UTF8` 写 JSON，避免乱码。
- **合并单元格**：python-docx 中合并单元格会重复出现在 `row.cells` 里，验证输出时按 `cell._tc` 去重，否则同一格内容重复出现。
- **上次残留数据**：脚本只清数据行（序号 1/2 所在行），不清头部和审批栏；审批栏有旧签名时需先确认是否清空。

## 演进

脚本随使用迭代。发现模板改版、新字段或新的口述表达方式时，更新本文件和 `fill_a036.py`，并在本文件记录变更。
